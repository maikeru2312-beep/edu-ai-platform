# 第6回審査 — ポジショニングの変更と作業範囲の記録

本書は、第6回で行った **サイトの自己定義の変更** と、**指示書の範囲から外れた判断** を記録する。
数値・実測はすべて `00-current-state.md` の計測に基づく。

---

## 1. なぜ positioning を変えたか

第5回までに、公開記事の再構築・一次資料確認・claim/source audit・utility asset・架空例・
privacy/About/AdSense disclosure・semantic internal-link repair・redirect repair・render audit・
lint/typecheck/test/validate/build・independent review は相当程度実施済みだった。
それでも「有用性の低いコンテンツ」で不承認になった。

したがって第6回の仮説は **individual page quality ではなく site-level の問題** である。
実測すると、次の3点が同時に成立していた。

1. **サイトが自分を aggregator と名乗っていた。**
   homepage hero が「最新情報を**収集・整理**してお届けします」、Footer が
   「情報を収集・整理し…個人運営の**情報メディア**です」。
   記事側には判断手順・様式・架空例という一次的な価値があるのに、
   サイトの自己定義がそれを「他所の情報の整理」と説明してしまっていた。
2. **主題が実態とずれていた。**
   About の「扱うテーマ」6項目のうち **助成金・補助金** と **研修・セミナー** は公開記事 **0件**。
   一方カテゴリ分布では AI校務改善が6件で最大であり、サイトは「生成AI情報サイト」に見えていた。
3. **記事どうしが同じ読者ジョブを重複所有していた。**
   canonical 15本の全105ペアを分類したところ、**OVERLAP_REQUIRES_REPAIR が37ペア**。
   重複は無作為ではなく、7つの共有ブロックに集中していた（`02-distinctness-matrix-initial.csv`）。

## 2. 変更後のポジショニング

「情報を知る」で終わらず、次まで扱うことを site-level のコピーで明示した。

- 何を確認するか / どう判断するか / どこで止まるか / 誰につなぐか / 何を記録するか / どう見直すか

### カテゴリを「情報の箱」に見せない

カテゴリ数は増やしていない（公開記事があるのは4つのまま）。
代わりに、各カテゴリに「何を決めるための区分か」を名指しする説明文を持たせ、
カテゴリページと homepage の両方に「いずれも特別支援教育を含む学校実務での判断を扱う区分です」を置いた。
AI・ICTの school workflow 記事を隠してはいない（AI校務改善3件・ICT活用3件・教材支援ツール3件は公開のまま）。

記事分布も専門性を裏づける形になった。

## 3. 指示書の範囲を超えた判断（要 owner 確認）

### 3.1 KEEP 記事2件に、小さな独自資産を追加した

指示書 §5 は KEEP 11記事について「大規模リライトをしない」としている。
一方 §10 は「単なる `OFFICIAL_SOURCE_SUMMARY` だけの canonical article は禁止」としている。

独立プロファイリングの結果、KEEP 指定の次の2件がこの禁止条件に該当していた。

| slug | 判定 | 資産の状態 |
|---|---|---|
| `reasonable-accommodation-school-record` | OFFICIAL_SOURCE_SUMMARY / 汎用度 HIGH | 「実質 NONE に近い」。手続は parent-collaboration、ICT は ict-reasonable-accommodation、計画は individual-education-plan へ既に明け渡している |
| `special-needs-visual-schedule-support` | PROCEDURE_GUIDE / 汎用度 HIGH（60〜70%） | 名前のついた再利用資産が無い |

**判断**: §10 は「禁止」という強い条件であり、§5 の「大規模リライトをしない」は
*方法* の制約であって *結果* の免除ではないと解釈した。
そこで両記事には **既存節の格上げ＋総論の圧縮** という最小の追加のみを行い、
名前のついた再利用資産を1つずつ持たせた。全面書き直しはしていない。

owner がこの解釈を採らない場合、該当2件は「資産なしのまま canonical に残す」か
「§10 の対象外とする」かの裁定が必要になる。

## 4. 行っていないこと

指示書 §2 の禁止事項はすべて遵守した。

- 新規SEO記事の追加なし。記事数は 21 → **15 に減少**（増やしていない）
- fake firsthand experience なし。`lib/article-experience-notes.ts` の確認済み範囲を
  一切広げていない。統合により未公開になった記事の注記は削除した
- 未立証の効果（「○時間削減」「○%改善」）の追加なし。機械チェックを追加した
- 実名・勤務校・自治体の公開なし
- AdSense 再審査申請なし
- Search Console の操作なし
- main への直接 push なし / main への merge なし
- 既存 privacy / security / legal accuracy を弱めていない
  （統合時、要配慮個人情報・匿名加工情報・仮名加工情報の区別は精度を保って統合先へ移した）
- 既存の第5回 acceptance を「テストを通すために削除」していない。
  審査対象セットの変更に伴う3件の更新は、いずれも **より強い不変条件へ差し替えている**
- utility asset の量産なし（追加した資産は REPAIR 4件＋§3.1 の2件のみ）
- 全記事を同一テンプレートへ揃えていない（むしろ鋳型を崩す方向へ変更した）
