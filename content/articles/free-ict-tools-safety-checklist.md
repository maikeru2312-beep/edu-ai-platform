## この記事で扱う範囲

「同僚に教えてもらった無料の練習アプリを、明日の授業で使いたい」。このとき詰まるのは操作ではなく、**その手前の「使ってよいのか」**です。

この記事は、**学校として正式に導入されていない外部のICTサービスについて、授業で使ってよい状態かを判断する**ための手順を扱います。AIサービスも含みますが、AI固有の論点は別記事に委ねます。

**扱わないもの**（それぞれ別の記事が担当します）

- **どのツールを選ぶか**（授業目的・操作性・アクセシビリティからの選定）→ [教員向けICT教材・支援ツールの選び方：授業と特別支援で使いやすい観点](/articles/ict-teaching-tools-selection-guide)
- **AIサービス固有の確認**（学習利用、生成物の扱い、出力の責任）→ [教育AIサービスを学校で使う前に確認したいこと｜個人情報・規約・安全性のチェックリスト](/articles/education-ai-service-checklist-before-use)
- **生成AIに何を入力するか**の線引き → [学校で生成AIを使うときの個人情報・セキュリティの注意点【教員向け】](/articles/school-generative-ai-privacy-security)

**選ぶことと、使ってよい状態かを判断することは別です。** どれだけ授業に合うツールでも、学校として使える状態でなければ使えません。

> この記事は一般的な確認の観点を整理したものです。特定のサービスを推奨・保証するものではなく、法的・行政的な判断を代行するものでもありません。**実際の可否は、所属校・設置者の定めが優先します。**

## 「無料かどうか」は安全性の判定軸ではない

最初に外しておきたい前提があります。

**無料だから危険、有料だから安全、ということはありません。** 無料は読者の入口条件であって、安全性そのものの判定軸ではありません。有料でも児童生徒のアカウントが必要なサービスはありますし、無料でもアカウント不要で情報が外に出ないサービスはあります。

判断を分けるのは、次のような点です。

- 学校・設置者がそのサービスの利用を認めているか
- 契約・登録の主体は誰か
- 児童生徒自身のアカウントが必要か
- どの情報が外部へ出て、どこに保存されるか
- 公開・共有される範囲はどこまでか
- 終わるときにデータを回収・削除できるか

無料であることが関係するのは、**約款（利用規約）を提示されるだけで、こちらから条件を交渉できない**サービスが多い、という傾向です。ただしこれは相関であって、無料かどうかで区分されているわけではありません。文部科学省のガイドラインも、後述する「約款による外部サービス」について**有償、無償に関わらず**と明記しており、区分の基準は料金ではなく**条件設定の余地があるかどうか**です。

### 「約款による外部サービス」という区分

文部科学省の[教育情報セキュリティポリシーに関するガイドライン（令和7年3月）](https://www.mext.go.jp/content/20250325-mxt_jogai01-100003157_1.pdf)は、**約款による外部サービス**を次のように定義しています。

> インターネット上に約款を掲示し、同意した利用者に対して情報処理機能を提供するサービス

そして、SaaS型パブリッククラウドサービスの一種ではあるものの、個別に契約を結ぶ型のサービスとは**別種**であり、**利用者が必要とする情報セキュリティに関する十分な条件設定の余地があるものを除く**、としています。同ガイドラインは、ここでいう約款による外部サービスが**個人向けのWebサービスを想定したもの**であり、約款を提示する形態のサービス全般がそのまま該当するわけではないことも注記しています。

つまり「条件を交渉できず、提示された約款を受け入れるかどうかしかない」サービスが、この区分です。同ガイドラインは、こうしたサービスについて**教育情報システム管理者が「利用してよい範囲」「業務により利用する約款による外部サービス」「利用手続及び運用手順」を規定しなければならない**という対策基準の例文を示しています。

そして教職員については、**対策基準の例文として次を示しています**。

> 教職員等は、利用するサービスの約款、その他提供条件から、利用に当たってのリスクが許容できることを確認した上で約款による外部サービスの利用を申請し、適切な措置を講じた上で利用しなければならない

**確認と申請が前提**であり、確認だけで使い始めてよいとはされていません。同ガイドラインは、**個人アカウントにより無断で約款による外部サービスを取り扱うことはセキュリティポリシー違反であり、学校の情報セキュリティ管理をすり抜ける行為である**とも注記しています。

ただし、このガイドラインは**主に教育委員会がポリシーを策定・見直しする際の参考**として示されたもので、第2編は「対策基準（例文・解説）」です。実際に義務となるのは、設置者がこれを対策基準として定めた後です。**自校・設置者に何が定められているかが出発点**になります。この記事の手順は、その定めに沿って「リスクが許容できることの確認」を実際に行うためのものです。

## 判断の流れ

5つのゲートを上から順に通します。**どこかで止まったら、その先の条件が整っても児童生徒には使わせません。** 確認そのものは続けてかまいません。

```
START
 ↓
Gate 1  学校・設置者のルール上、外部サービスを使えるか
 ↓  認められないと確認できた → DO NOT USE
 ↓  ルール・経路が不明／申請済みで回答待ち／端末でブロックされている → HOLD
Gate 2  児童生徒自身のアカウント作成が必要か
 ↓  学校発行アカウントで登録できないと確認できた → DO NOT USE ／ 登録可否・利用資格が未確認 → HOLD
Gate 3  児童生徒・学校の情報が外部へ送信・保存されるか
 ↓  要配慮個人情報が出る → 設置者の手続きへ上げる（HOLD）／必要でなければ DO NOT USE
 ↓  何が出るか読み取れない → HOLD
Gate 4  公開・共有機能があるか
 ↓  公開範囲を教員が制御できない／広告が授業の使い方に収まらないと確認できた → DO NOT USE
 ↓  画面に何が出るか未把握／確認に登録が必要で Gate 1 の回答待ち → HOLD
Gate 5  終わるときにアカウント・データを回収／削除できるか
 ↓  消去の方法がなく、かつ扱ってよい情報に絞ると授業が成り立たないと確認できた → DO NOT USE
 ↓  削除・書き出しの方法があるかどうか分からない → HOLD
USE（所属校の手続きを通したうえで使う）
```

図は各ゲートの要約です。**判定はゲートごとの「判定」欄に従ってください。**

結論は3つです。

| 判断 | 意味 |
|---|---|
| **USE** | 確認が済み、所属校の手続きを通したうえで使う |
| **HOLD** | 確認できていない項目がある。**使わずに確認を進める** |
| **DO NOT USE** | 使わないと決めた。理由を残す |

判定語は、**確認できたかどうか**で使い分けます。**「まだ分からない」は DO NOT USE ではなく HOLD**、**「使えないと確認できた」が DO NOT USE** です。DO NOT USE は教員の裁量での結論であって、設置者の判断で後から覆ることはあります。

**すべての項目を埋めれば自動的に使ってよい、ということではありません。** ゲートは「使える条件が揃っているか」を見るもので、最後は学校としての判断です。

判定に迷ったときの原則は共通しています。**規約や説明に書かれていないことは、「問題ない」ではなく「判断材料が足りない」**です。読み取れなければ HOLD です。

### 「止まる」の意味

ここでいう「止まる」は、**児童生徒に使わせないこと**です。教員が確認のために画面を開くことまで禁じる意味ではありません。Gate 4 のように、実際に開いてみないと確認できない項目もあります。

ただし3点、区別してください。

- **教員が試すときも、児童生徒の情報は入力しません。** 架空のデータか、教員自身の情報の範囲で確かめます
- **学校端末の設定変更をともなう確認はしません。** インストール制限やフィルタリングを個人の判断で回避しないでください（Gate 1 参照）
- **新規のアカウント作成や約款への同意をともなう確認は、Gate 1 の判定が出てから行います。** 約款に同意した時点で、それ自体が利用の開始にあたり得るためです。申請しただけの段階では登録せず、**登録せずに見られる範囲**（公開されている説明・デモ・利用規約・プライバシーポリシーの画面）にとどめてください

3点目は、ガイドラインが**個人アカウントによる無断の取扱いをセキュリティポリシー違反**としていることに直接かかわります。「確認のためだから」という理由でも、個人アカウントでの先行登録はしないでください。

### Gate 1：学校・設置者のルール上、使えるか

**最初に確認するのはサービスの中身ではなく、自校のルールです。**

ガイドラインは、利用してよい範囲・利用する外部サービス・利用手続を**教育情報システム管理者が規定する**という例文を示しています。つまり「どこに聞けばよいか」は自治体・学校ごとに定められるもので、**全国共通の確認順序はありません。**

この記事では、確認の順番を「まずICT担当、次に管理職、次に教育委員会」のように固定しません。**所属校・設置者が定めた確認経路に乗せてください。**

- 承認済みサービスの一覧や、利用申請の手続きが定められているか
- 定められている場合、そのサービスは対象に入っているか

#### 確認経路が分からないとき

「誰に聞くか」は自治体・学校ごとに違うので指定できませんが、**どこを見れば経路が書いてあるか**は共通して探せます。

- 設置者の**教育情報セキュリティポリシー本体**（自治体サイトで公開されている場合、校務用の共有フォルダに置かれている場合があります）
- **承認済みサービス一覧・利用申請様式**が配付されていないか
- **年度当初に配付された規程・手引き**、職員会議で共有された資料
- 校内の情報セキュリティ担当・情報主任等が置かれている場合、その職の分掌

見つからないときは、**「このサービスを使ってよいか」ではなく「外部サービスを使うときの手続きはどこに定められているか」を聞いてください。** 手続きの所在を尋ねる形にすると、相手に可否判断を委ねずに済みます。

#### 端末の設定でブロックされている場合

学校端末でそのサービスが開けない、インストールできない、という状態は、**Gate 1 の答えがすでに出ている可能性**を示します。フィルタリングやインストール制限は、設置者や学校の判断で設定されていることが多いためです。

**個人のスマートフォンのテザリング等で回避しないでください。** 授業に必要だと考えるなら、所属校の手続きに乗せて解除や許可を申請します。**技術的にアクセスできることは、使ってよいことを意味しません。**

ガイドラインも、個人アカウントで無断に外部サービスを取り扱うことは**セキュリティポリシー違反であり、学校の情報セキュリティ管理をすり抜ける行為**だと注記しています。同じ注は、**一概に利用を禁止するものではなく、情報セキュリティ管理者が教職員等の利用を把握できる状態にすることが重要**だとも述べています。申請して把握できる状態にすることが、使うための道筋です。

#### Gate 1 の判定

- 外部サービスの利用が**認められていない**、または利用できないと回答されたことを確認できた → **DO NOT USE**
- ルールや確認経路が**見つからない**、または**申請して回答待ち** → **HOLD**（確認先と確認日を記録する）
- **学校端末で技術的にブロックされている**（可否の回答はまだ得ていない） → **HOLD**（所属校・設置者の確認経路に乗せ、解除・利用許可の可否を確認する）
- 手続きに乗せて**利用してよい旨の回答を得た**、または**申請が不要であることを確認できた** → **Gate 2 へ**

ブロックされていること自体は DO NOT USE ではありません。**解除や許可の可否を確認していない**という状態です。逆に、**技術的に開けることも利用可を意味しません。** どちらの場合も、判定は確認経路からの回答で決まります。

**Gate 1 を通過するのは、申請した時点ではなく回答を得た時点です。** 申請中は HOLD のまま、登録をともなわない範囲で以降のゲートの確認を進めます。

**分からないまま児童生徒に使わせない。** ここが最初のゲートです。

### Gate 2：児童生徒自身のアカウント作成が必要か

アカウントが要るかどうかで、確認の重さが大きく変わります。

- **アカウント不要で使える** → 登録に関する確認は少なくなります（ただし利用資格の確認と Gate 3 以降は残ります）
- **教員のアカウントだけで使える** → 学校として発行されたアカウントで登録できるかを確認します
- **児童生徒自身のアカウントが必要** → 最も確認が重くなります

**アカウントの要否にかかわらず、年齢や利用資格の条件は、そのサービスの現行の約款・利用規約で確認してください。** 登録を求めないサービスでも、規約で対象者が限定されていることがあります。海外の法律を根拠に「何歳以上なら大丈夫」と一般化はできません。条件はサービスごとに異なり、変更もされます。

**教員個人のメールアドレスで学級分のアカウントを作らない**、というのは実務上の要点です。異動や退職でアカウントが誰にも管理できなくなります。学校として発行されたアカウントで登録できないことが確認できたなら、**教員個人のアカウントで代替せず、アカウント不要のサービスに切り替える**のが現実的です。

#### Gate 2 の判定

利用資格とアカウントは別の軸です。両方を見ます。

- 現行の約款・利用規約を確認した結果、**今回の児童生徒・利用者が利用資格を満たさない（対象外である）と確認できた** → **DO NOT USE**（アカウントの要否にかかわらず、ここで止まります）
- 児童生徒または教員のアカウントが必要で、**学校発行アカウントでは登録できないと確認できた** → **DO NOT USE**（教員個人のアカウントで代替しない。別のサービスを検討する）
- **年齢・利用資格の条件が現行の規約から読み取れない**、または学校発行アカウントで**登録できるかどうかが未確認** → **HOLD**
- 利用資格を満たすことを確認でき、かつ**アカウント不要、または学校発行アカウントで登録できる** → **Gate 3 へ**

教員のアカウントだけで使える場合も、判定は同じです。**学校として発行されたアカウントで登録できるか**を見ます。Gate 4 の実機確認も学校発行の教員アカウントで行うため、ここが通らないと以降が進みません。

### Gate 3：児童生徒・学校の情報が外部へ送信・保存されるか

確認するのは入力欄だけではありません。

- 氏名・学年・学級・出席番号などの**入力項目**
- **写真・音声・動画**（撮影機能がある場合を含む）
- **児童生徒の作品**（作文・絵・スライドなど）
- **学習ログ**（回答履歴、利用時間、正誤の記録）
- **端末やアカウントの情報**（メールアドレス、識別子）

とくに注意が要るのが、**障害の状態、診断名、支援や配慮の内容**です。障害があることや、病歴、健康診断その他の検査の結果を示す記述が含まれる個人情報は、個人情報保護法上の**要配慮個人情報**にあたり、不当な差別や偏見が生じないよう特に配慮を要するものとされています。支援や配慮の内容そのものは、それ自体が直ちに要配慮個人情報にあたるとは限りませんが、**障害があることを推知させる**ため、同じ慎重さで扱ってください。

これらは、設定欄・自由記述欄・作品の内容・支援機能の利用記録など、**氏名欄以外の場所から出ていくことがあります。**

**要配慮個人情報が外部に出る設計のサービスを、教員の判断で USE にしないでください。** 授業に必要だと考えるなら、**設置者の手続きに上げたうえでの HOLD** とし、結論が出るまで児童生徒には使わせません。必要でないと判断できるなら、その場で **DO NOT USE** として理由を残します。

**氏名欄がないことは「個人が分からない」ことを意味しません。** 学級・出来事・作品の内容・利用時刻などの組み合わせで、校内では本人にたどり着くことがあります。氏名を入れない設計にしたとしても、それだけで匿名になったとは扱わないでください。

なお、外部サービスに情報が保存されること自体が、ただちに法律上の第三者提供にあたるとは限りません。個人情報保護委員会は、クラウドサービスの利用が第三者提供や委託にあたるかの判断基準を、**保存されている電子データに個人データが含まれるかどうかではなく、その事業者が個人データを取り扱うこととなっているかどうか**だとしています。契約条項で事業者が取り扱わない旨が定められ、適切にアクセス制御が行われている場合は、本人の同意も監督義務も要しないとされています。

**ただし、このQ&Aは民間事業者向けのガイドラインに関するものです。** 公立学校は行政機関等として個人情報保護法第5章の規律を受けるため、条文がそのまま同じではありません。ここで参照しているのは「外部保存＝提供」ではないという**考え方の部分**であり、自校で何が必要かは設置者の定めで確認してください。

そして**いずれの整理でも、利用する側の安全管理措置の責任は残ります。** 「委託にあたらないから何もしなくてよい」ではありません。約款によるサービスでは、こうした条項を個別に取り決めること自体が困難な場合があります。

#### Gate 3 の判定

- **要配慮個人情報が外部に出る** → 教員限りで USE にしない。授業に必要なら**設置者の手続きに上げて HOLD**、必要でなければ **DO NOT USE**
- 規約や画面から、**何が送信・保存されるのか読み取れない** → **HOLD**
- 出ていく情報の範囲を確認でき、その範囲なら扱ってよいと判断できた → **Gate 4 へ**
- 設置者の手続きに上げた結果、**扱ってよい旨の回答を得た** → **Gate 4 へ**（回答の内容と条件を記録する）

### Gate 4：公開・共有機能があるか

作品を共有できるサービスでは、**初期設定でどこまで見えるか**を実際に確かめてください。説明を読むだけでは分かりません。登録が必要なサービスなら、**学校から発行された教員アカウント**で、Gate 1 の回答を得たうえで確認します（「「止まる」の意味」参照）。

- 公開範囲の初期値はどこか（本人のみ／同じ学級／サービス全体／インターネット全体）
- 教員が公開範囲を制御できるか
- 児童生徒が自分で公開範囲を変えられるか
- 作品に氏名や学校名が入る設計になっていないか

児童生徒の作文や絵、スライドなども、思想や感情を創作的に表現したものであれば著作物にあたり、**本人に著作権が生じます。** ガイドラインは、約款による外部サービスのリスクのひとつとして、**利用者データの利用権限がサービス提供者側に帰属することを前提にサービスが提供される場合がある**ことを挙げています。公開機能を使う場合は、アップロードされた作品の扱いを定めた条項を確認してください。

広告や外部リンクが表示されるかも、ここで見ます。表示されること自体が問題ではなく、**授業中に児童生徒の画面に何が出るかを事前に把握しているか**が確認事項です。

#### Gate 4 の判定

まず、**公開・共有機能があるかどうか**を実際に開いて確かめます。

- **公開・共有機能がないと確認できた** → 公開範囲の確認は不要。下の広告・外部リンクの確認へ進みます
- 公開・共有機能がある → 以下の停止条件と通過条件で判定します

停止する条件

- 公開範囲を**教員が制御できない**と確認できた（既定がインターネット全体への公開で、その設定を変更できない場合を含む） → **DO NOT USE**
- 広告や外部リンクの内容を把握したうえで、**授業での使い方に収まらない**と判断した → **DO NOT USE**
- **実際に開いて確認していない**（説明を読んだだけ） → **HOLD**（確認してから判断する）
- **確認にアカウント作成が必要で、Gate 1 の回答がまだ出ていない** → **HOLD**（先に登録しない）
- 広告や外部リンクが表示されるが、**児童生徒の画面に何が出るかを把握できていない** → **HOLD**（確認してから判断する）
- 広告や外部リンクの内容は**把握したが、授業での使い方に収まるかをまだ判断していない** → **HOLD**（判断してから進む）

通過する条件（すべて満たすこと）

- 公開・共有機能がない、または**公開範囲を教員が制御できる**
- 画面に何が出るかを**実際に開いて確認できた**
- 広告や外部リンクがある場合、その内容が**授業での使い方に収まると判断できた** → **Gate 5 へ**

なお、既定の公開範囲が広いこと自体は DO NOT USE の理由になりません。**教員が変更できるかどうか**が分かれ目です。

広告や外部リンクは、次の4つの状態で判定が決まります。表示されること自体は理由になりません。

| 状態 | 判定 |
|---|---|
| 何が出るか**把握していない** | HOLD |
| 把握したが、**授業での使い方に収まるかを判断していない** | HOLD |
| 把握したうえで、**収まらない**と判断した | DO NOT USE |
| 把握したうえで、**収まる**と判断した | Gate 5 へ |

### Gate 5：終わるときに回収・削除できるか

始める前に、終わり方を決めます。ガイドラインは、約款による外部サービスを使う際の**リスクへの対策として**次を挙げています。

- **サービスの突然の停止に備え、あらかじめ代替サービスを確認しておく**
- 情報が滅失し復元できなくなる場合に備え、**バックアップを取得する**
- **約款や利用規約が予告なく一方的に変更されてセキュリティ設定が変わる場合や、一度記録された情報を確実に消去できない場合に備え、そのサービスで取り扱うことのできる情報をあらかじめ定めておく**

3つ目が要点です。「消せないかもしれない」を前提に、**入れる情報のほうを先に絞る**という考え方です。

個人情報保護委員会も、学校からの漏えい等報告を分析した注意喚起（2025年6月25日）で、事案例・発生原因・再発防止策を学校設置者および教職員向けに示しています。**学校では、そもそも情報が外に出る事案が起きている**という前提に立つなら、入れる情報を先に絞る設計のほうが、実務では破綻しにくくなります。

- データの書き出し（エクスポート）ができるか
- アカウントの削除方法があるか
- 年度末や担当交代のときに、誰が何をするか

#### Gate 5 の判定

- 消去・回収の方法がなく、かつ**扱ってよい情報の範囲に絞ると授業が成り立たない**ことを確認できた → **DO NOT USE**
- 削除・書き出しの方法が**あるかどうか分からない** → **HOLD**（方法の有無を確認してから判断する）
- 削除・書き出しの方法を**確認できた**、または**方法がないと確認したうえで扱ってよい情報の範囲を定められた** → **USE の判断へ**（所属校の手続きを通してから使う）

「方法がない」と確認することは、この段階では停止理由になりません。**分からない**ままにしないことが条件です。

## 利用規約のどこを見るか

規約を全文読む必要はありません。一方で、決まったキーワードを検索すれば十分とも言えません。**サービスによって文書の構成も用語も違う**ためです。

見るべき領域を持っておき、そのサービスの文書構造に合わせて探してください。

| 領域 | 何を知りたいか |
|---|---|
| 利用資格・年齢 | 誰が使えるサービスか。児童生徒が対象に入るか |
| アカウント | 登録に何が必要か。学校として管理できるか |
| 収集する情報 | 何を集めるか。入力欄以外に何を取得するか |
| 利用目的 | 集めた情報を何に使うか。改善や学習に使うか |
| 第三者提供・委託 | 外部に渡るか。渡る場合は誰にか |
| 保存 | どこに、いつまで保存されるか |
| 公開 | 何がどこまで公開されるか |
| コンテンツ・著作権 | アップロードした作品の権利がどう扱われるか |
| 解約・削除 | やめるときに何ができるか |
| 規約の変更 | どう通知されるか |

ガイドラインは、**教育情報システム管理者が**、約款による外部サービスについて、**利用者が登録した情報が同意なく無断使用（目的外利用、第三者への提供等）されないこと**と、**事業者が業務上知り得た情報の守秘義務が守られること**が約款に規定されているかを確認しなければならない、という対策基準の例文を示しています。

つまりこの2点は、本来は管理者側が確認する事項です。**教員が一人で結論を出す性質のものではありません。** 上の表の領域のうち「利用目的」「第三者提供・委託」がここに対応するので、規約の該当箇所を見つけたら、その箇所を確認経路に渡してください。

条文の意味が取りにくいときも同じです。その条文だけを絞って持ち込んでください。全部を理解してから相談する必要はありません。

## 確認例（完全な架空の事例）

> 以下は**完全に架空の事例**です。実在するサービス・学校・児童生徒の事例ではありません。

**きっかけ**：同僚から「アカウント不要で使える無料の漢字練習Webサービスがある」と聞き、明日の授業で使いたい。

一見すると、アカウント不要・氏名入力なしで、確認することは少なそうに見えます。順に通します。

| 項目 | 記入例 |
|---|---|
| サービス名・提供元・URL | （架空）漢字ドリルWeb／提供元は国内の個人開発者と記載あり／URLは記録済み |
| 利用目的 | 4年生の国語、単元末の10分間の練習 |
| 誰が使うか | 児童（学校端末のブラウザ） |
| **Gate 1**：学校・設置者の利用ルールと確認経路 | 自治体の承認済み一覧に**記載なし**。申請の手続きは規程に定められていた。その経路でICT担当へ照会中 |
| **Gate 1**：既に承認済みか | いいえ |
| **Gate 1**：申請状況 | 申請済み・回答待ち |
| 契約・登録する主体 | 登録なし |
| **Gate 2**：児童生徒アカウントの要否 | **不要**。ここは軽い |
| **Gate 2**：学校発行アカウントで登録できるか | 該当なし（教員分も登録不要） |
| **Gate 2**：年齢・利用資格の確認先と結果 | 利用規約を確認したが、年齢・利用資格の記載が見当たらない。**確認できず** |
| **Gate 3**：入力する情報 | 氏名欄なし |
| **Gate 3**：要配慮個人情報が出るか | **出ない**。障害・診断・支援内容の入力欄も自由記述欄もなし |
| **Gate 3**：写真・音声・作品・学習ログの扱い | 写真・音声・作品はなし。**回答履歴が保存される**旨の記載あり |
| **Gate 3**：保存される場所と範囲 | 「端末に保存」と読める記載はあるが、外部へ送信されるかは**記載が見当たらない** |
| **Gate 3**：設置者・学校の確認手続きに上げた場合の回答内容・利用条件 | 該当なし（要配慮個人情報が出ないため、手続きには上げていない） |
| **Gate 4**：公開・共有機能の有無と、初期設定を実際に確認したか | **共有機能なし**。実際に開いて確認済み |
| **Gate 4**：何で確認したか | **登録不要**のため、アカウントを作らずに確認できた |
| **Gate 4**：教員が公開範囲を制御できるか | 機能なし（該当なし） |
| **Gate 4**：広告・外部リンクの有無と、授業での使い方に収まるか | **広告あり**。学習と無関係な外部サイトへのリンクが表示された。**収まるかは未判断** |
| アカウントの管理機能 | 該当なし（アカウントを作らない） |
| **Gate 5**：データの書き出し・削除方法 | 記載が見当たらず、**あるかどうか分からない**（端末側の履歴を消しても、外部に送信されていた場合には届かない） |
| **Gate 5**：このサービスで扱ってよい情報の範囲を定めたか | **未定**（Gate 3 の保存範囲が確定しないと定められない） |
| **Gate 5**：利用終了時・担当交代時の処理 | 未定（同上） |
| 誰へ確認したか・確認日 | ICT担当へ規程の経路で照会（◯月◯日）。回答待ち |
| **判断** | **HOLD** |
| 判断理由 | Gate 1 未通過（申請の回答待ち）。Gate 2 の利用資格が規約から確認できない。Gate 3 の外部送信の有無と保存場所が読み取れず、Gate 5 の「扱ってよい情報の範囲」もそれに連動して定められない。Gate 4 は広告の内容まで把握できたが、10分間の練習という使い方に収まるかは、Gate 1 の回答を得て単元の進め方を決めてから判断する |
| 次に何を確認するか・誰が行うか | ①ICT担当からの回答（申請の要否）②規約の利用資格・保存に関する記載の有無を再確認（授業者） |
| いつまでに確認するか | ◯月◯日まで。それまでに確認できなければこの単元では使わない |
| その日までの代替手段 | 承認済みの学習支援ツール、または紙のドリル |

**この例で分かること**

- **アカウント不要でも、確認が終わるとは限りません。** Gate 2 のアカウント欄が軽くても、Gate 1・2（利用資格）・3・5 が残ります
- **「規約に書かれていない」は「問題ない」ではありません。** 保存場所や外部送信の記載が見当たらないことは、判断材料が足りないという状態です
- **前のゲートが確定しないと、後のゲートも確定しません。** この例では、Gate 3 で外部送信の有無が分からないため、Gate 5 の「消せるか」も答えが出ません。端末の履歴を消すだけで足りるかどうかは、Gate 3 の答え次第です
- HOLD は「使ってはいけない」ではありません。**確認が済むまで使わない**という状態です。ICT担当の回答と規約の追加確認で、USE に動くことも DO NOT USE に動くこともあります
- **HOLD には期限と代替手段を書いておきます。** 回答が来ないまま授業日を迎えたときに、なし崩しで使う状態を避けるためです

**明日の授業をどうするか**は別に決めます。この例なら、承認済みの学習支援ツールやプリントで同じ活動ができないかを先に検討します。**慎重に確認することと、何も使わないことは違います。**
