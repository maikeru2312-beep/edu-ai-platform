タイマーアプリ、読み上げ、AACアプリ——支援ツールの紹介記事はいくらでも見つかります。困るのはたいてい紹介のあとです。目の前の子に合うのはどれなのか、どのくらい試せば判断できるのか、合わなかったときに何を変えればよいのか。この記事は、製品を並べるのではなく、その判断を一続きの手順として扱います。

> 本記事は一般的な情報提供を目的としています。具体的な支援方針・ツール導入の判断は、本人・保護者・関係機関と連携の上、所属校・教育委員会の方針に従って進めてください。個別の医療的・診断的判断を代行するものではありません。

→ 使うことを合理的配慮として位置づけるか、指導の手立てとするかの整理は[そのICT利用は合理的配慮か、教育課程上の指導か](/articles/special-needs-ict-reasonable-accommodation)で扱っています。

## この記事がたどる判断の流れ

支援ツールの選択でつまずくのは、たいてい「どれを選ぶか」の一点に判断が集中しているときです。選ぶ前に何を決めておくか、選んだあと何を見るかまで含めて、次の順で進めます。

| 段階 | ここで決めること |
|---|---|
| 場面の観察 | どの場面で、参加・表現・理解のどれが妨げられているか |
| 目標 | その場面を、どういう形にしたいか |
| 機能 | そのために、何ができる必要があるか |
| 分類と候補 | その機能を持つのはどの種類か。端末の標準機能で足りないか |
| 試用の条件 | どのくらいの期間・どの場面で・誰が見て・何を記録するか |
| 観察 | 記録した事実（できごと・本人の様子） |
| 判定 | 続ける／調整する／変える／いったんやめる |

この流れは一方向ではありません。判定で「変える」になれば機能の段階に戻りますし、観察の途中で「そもそも目標の置き方がずれていた」と分かることもあります。戻れる形にしておくために、各段階で決めたことを短く書き残しておきます。

## 参加できていない場面を書き出す

出発点は、ツールの名前ではなく場面です。「読みに困難がある」という特性の名前だけでは、必要な機能は決まりません。同じ読みの困難でも、教科書の本文を追う場面と、板書を書き写す場面と、テストの問題文を読む場面とでは、必要になるものが違います。

書き出すときは、次の三つのどれが妨げられているかまで分けておくと、あとの段階で機能に落としやすくなります。

- 参加：その活動に入れているか（活動が終わるまでに手がつかない、途中で離れてしまう）
- 表現：自分の考えや要求を出せているか（伝える手段がない、時間がかかって機会を逃す）
- 理解：内容を受け取れているか（文字から受け取れない、口頭の指示が残らない）

一つの場面に複数が重なることもあります。その場合も、まず一つに絞ります。三つ同時に解決しようとすると、あとで何が効いたのかが分からなくなります。

## その場面を、増やしたい形に言い換える

「ICTで支援したい」は目標になりません。観察した場面を、増やしたい状態の形に言い換えます。

- 悪い例：読みを支援する
- 言い換えた例：国語の本文を読む場面で、内容を把握したうえで、そのあとの話し合いに一言でも入れるようにする

言い換えた形が、あとで観察項目になります。「内容を把握したうえで話し合いに入る」を目標に置いたなら、観察するのは操作の習熟ではなく、話し合いに入れた回数と本人の様子です。

## 必要な機能を言葉にする

目標が決まったら、製品名を探す前に、その目標のために何ができる必要があるかを言葉にします。先の例なら、次のようになります。

- 本文を音声で受け取れること
- いま読んでいる箇所が視覚的に分かること
- 本人が自分で止める・戻すができること

この段階を飛ばして製品を探し始めると、機能の多さや評判で候補が決まってしまいます。機能を先に書いておけば、候補が減ったときも「この機能を持つ別のもの」という形で探し直せます。

## 機能を満たす分類を探す

必要な機能が言葉になったら、それを持つのがどの種類かを見ます。ここでの分類は候補を探す入口であって、分類名で支援が決まるわけではありません。

### 端末に最初から入っている機能を確かめる

アプリを探す前に、同じ働きをする機能が手元の端末にすでにないかを見ます。読み上げや音声入力のように、専用のアプリを入れなくても標準機能として使えるものがあるためです。標準機能で足りる場合は、申請も費用も発生せず、更新や引き継ぎの負担も小さく済みます。

読み上げ・音声入力のほかに、次のような機能が端末に最初から用意されていることがあります。

- 動画や音声に字幕を表示する機能。音声だけでは聞き取りにくい場面で、文字と音声の両方から内容を受け取れるようにする
- 画面のタッチやボタン操作が難しい場合の、操作そのものを置き換える設定。スイッチによる操作、押す・長押しの受け付け方の調整など
- 使うアプリや操作できる範囲を一時的に限定する設定。画面上で触れられる対象を減らし、活動から離れにくくする

機能の名称、設定画面のたどり方、そもそも使えるかどうかは、OSの種類・端末の世代・設置者の管理設定によって変わります。ここで挙げたのは機能の働きであって、同じ名前の項目が手元の端末にあるとは限りません。紹介記事の名称で探すより、実際の端末の設定画面を開いて確かめ、管理設定で制限されている場合は校内の情報担当に相談するほうが確実です。

設定を変えたときは、いつ・どの設定を・どう変えたかを短く残しておきます。合わなかったときに元へ戻せますし、担当が替わったあとも同じ状態を再現できます。共用の端末では、他の子どもの使用に影響しないかもあわせて確認します。アプリを追加する場合は、そのアプリがOS標準の読み上げや拡大と干渉せずに動くかどうかを、試用の段階で確認します。

### 目的別の分類（一覧）

標準機能で足りないときに探す範囲を、目的で区切ったものが次の表です。分類は候補を探す入口として使い、選ぶ理由は前の段階で書いた機能のほうに置きます。

| 支援の目的 | この分類が担う機能 | 選ぶときに確かめること |
|---|---|---|
| 見通しを持つ | タイマー表示、スケジュールの提示、終わった活動を消す操作 | 本人が自分で操作でき、終わりが分かりやすいか |
| 伝える（AAC） | 絵・写真・文字・録音音声による意思表示と要求伝達 | 語彙と操作方法が本人の実態に合っているか |
| 読む・書く | 読み上げ、音声入力、ふりがな、文字サイズ・字間・配色の変更 | その場面で必要な機能に対応しているか |
| 記録する・振り返る | 写真・動画・音声での記録、記録の蓄積、体調や気持ちの入力 | 個人情報の保存先と管理方法が明確か |
| 感覚と注意を調える | 聴覚刺激の調整、画面の情報量を減らす表示、休憩のタイミング提示 | 本人の感覚特性に合い、過剰な刺激にならないか |
| 教員の教材準備 | 計画の書式、視覚支援教材の作成・印刷、引き継ぎ記録 | 児童生徒の個人情報を入力しない運用ができるか |

分類ごとに、間違えやすい点を短く添えます。

- 見通し支援は、画面のほうに注意が向きすぎることがあります。紙のスケジュール表や具体物との組み合わせを含めた形式の選び方は[視覚的な見通し支援の作り方：形式の選び方・予定変更の伝え直し・見直しの記録](/articles/special-needs-visual-schedule-support)で扱っています。
- AACは、伝える手段の選択肢を広げるためのものです。「言葉を使わなくなる」という懸念はよく挙がりますが、AACを使うことで言語表現が抑制されるという根拠はありません。言語指導や他の支援と組み合わせて使います。
- 読み書き支援は、読み書きの練習をしなくてよいという意味ではありません。何の目的で使うかを決め、他の学習活動と切り分けて使います。
- 感覚の特性は本人によって大きく異なります。決まった答えはなく、試して調整する前提で進めます。医療的な判断が必要な場面では専門機関と連携します。
- 教材準備に生成AIを使う場合、児童生徒の個人情報を入力しないことが原則です。記録や写真を外部サービスへ入力してよいかの線引きは[学校の校務で生成AIを使う前の判断ガイド](/articles/ai-koomu-kaizen-nyumon)の校務ゲート2で扱っています。

### AACは伝え方の型で分けて考える

AAC（拡大代替コミュニケーション）は、話し言葉だけに頼らずに意思を伝える手段の総称で、特定のアプリを指す言葉ではありません。候補を比べるときは伝え方の型で分けると、本人に求められることの違いが見えやすくなります。

| 伝え方の型 | 本人が行うこと | 確かめたいこと |
|---|---|---|
| 絵・写真・シンボルから選ぶ | 選択肢の中から選んで示す | 語彙の数と並び方が本人に合っているか |
| 文字を入力して音声で出す | 文字を打つ、または候補から選ぶ | 入力の負担が、伝えたい内容に見合っているか |
| 録音した音声を再生する | ボタンを押す | 用意した以外のことを伝えたい場面をどう補うか |
| 紙の絵カードを画面に置き換える | これまでと同じ選び方をする | 紙で成り立っていた手順が画面上でも保てるか |

型は候補を絞るための入口であり、これだけで決まるものではありません。AACの選定・調整は、言語聴覚士などの専門職や保護者と相談しながら進めることが前提です。校内だけで結論を出さず、専門職に相談することを前提に候補を絞る、という順序にしておきます。

## 候補が二つ以上あるときの比べ方

比べ方そのものを先に決めておかないと、機能の多さや評判で決まってしまいます。

### 使ってよいかの確認と、本人に合うかの判断を分ける

判断には性質の違う二つが混ざっています。一つは、そのサービスを学校として使ってよい状態かという前提の確認です。もう一つは、目の前の子どもに合っているかという支援上の判断です。

前提の確認は、支援の目的とは無関係に、満たしていなければそこで止まります。学校・設置者のルール、児童生徒のアカウントの要否、外部へ出る情報、公開・共有機能、終わるときの回収と削除といった観点です。この手順は[無料ICTツールを授業で使う前の確認手順](/articles/free-ict-tools-safety-checklist)が扱っているため、本記事では前提が通った候補を比べる側に絞ります。

順番を逆にしないことが要点です。本人に合いそうな候補を一つに絞り込んでから前提の確認で止まると、支援の見通しごと組み直すことになります。

### 支援手段が途中で止まらないかを確かめる

支援ツールは、その子の表出や理解の手段そのものになっていることがあります。教科の教材が一時的に使えないのとは、止まったときの意味が違います。候補の段階で次の三つを確認しておきます。

- 通信が不安定なときや校内ネットワークが止まったときに、最低限の機能が使えるか
- 使えない日にどうするか（紙のカード、具体物、教員が読み上げるなど）を決めてあるか
- 提供が終了したときや仕様が変わったときに、作り込んだ内容を持ち出せるか

三つ目は見落としやすい点です。AACの語彙やシンボルの並び、スケジュールに使った写真、記録の蓄積は、その子に合わせて調整を重ねたものです。書き出し（エクスポート）ができない仕様だと、乗り換えのたびに作り直しになります。

### 候補比較シート

点数をつけて合計で決めるための表ではなく、空欄を残さないための表です。確認できていない欄は空欄のままにせず「要確認」と書き、誰に聞けば分かるかまで記録します。

| 確認軸 | 候補A | 候補B | 確認する相手・資料 |
|---|---|---|---|
| 参加できていない場面と、そこでの目標 |  |  | 個別の指導計画、授業の記録 |
| その場面で必要になる機能 |  |  | 公式の機能説明 |
| 本人が自分で操作できたか |  |  | 試用時の本人の様子 |
| 本人が使うことに抵抗を示さなかったか |  |  | 試用時の本人の様子、本人への確認 |
| OS標準機能との干渉の有無 |  |  | 試用時の動作、公式ヘルプ |
| 通信が使えないときの動作と代替手段 |  |  | 試用時の動作、授業の計画 |
| 作った内容の書き出し可否 |  |  | 公式ヘルプ |
| 準備・更新を続けられる負担か |  |  | 担当者間の相談 |
| 次年度・他の教員へ引き継げるか |  |  | 担当者間の相談 |
| 前提の確認が済んでいるか |  |  | 管理職、情報担当、設置者 |

## 試用の条件と、決める前の確認を一枚にする

候補が絞れたら、使い始める前に次のシートを埋めます。上段は使い続けられるかどうかの確認、下段は試用の条件です。埋まらない欄が残っている状態では、あとで何を根拠に判断したのかが再現できません。

| 区分 | 確認すること | 記入欄 |
|---|---|---|
| 目的 | 参加できていない場面と、増やしたい形を書けているか |  |
| 目的 | ツールを使うこと自体が目標になっていないか |  |
| 本人との合致 | 本人が操作できるか（支援があれば使えるかを含む） |  |
| 本人との合致 | 本人が使うことに抵抗を示していないか |  |
| 本人との合致 | 発達段階・感覚特性に合っているか |  |
| 継続・引き継ぎ | 担当教員が準備・更新を続けられる負担か |  |
| 継続・引き継ぎ | 学年をまたいで引き継げる仕様か |  |
| 継続・引き継ぎ | 家庭と共有する必要があるか。保護者へ説明したか |  |
| 安全・管理 | 写真・音声・記録の保存先と管理方法が明確か |  |
| 安全・管理 | 外部サービスへのデータ送信について校内ルールを確認したか |  |
| 安全・管理 | 導入・更新について管理職・情報担当と確認済みか |  |
| 試用の条件 | いつからいつまで試すか（期間） |  |
| 試用の条件 | どの場面で使うか（一つに絞る） |  |
| 試用の条件 | 誰が様子を見るか |  |
| 試用の条件 | 何を記録するか（目標を言い換えた観察項目） |  |
| 試用の条件 | 見直す日 |  |

最後の「見直す日」は、使い始める前に決めておく欄です。合うかどうかは使ってみないと分からないため、いつ確認し直すかを先に置いておかないと、合わないまま続くか、いつの間にか使われなくなるかのどちらかになりやすくなります。

運営者は、本人の様子を確認しながら支援ツールの候補を絞る場面に関わってきました。その範囲での観察として、決めた時点では合っていたものが、しばらく経つと使われないまま置かれている、ということがありました。見直す日を先に置くのは、そのためです。

## 観察した事実から、続ける／調整する／やめるを決める

見直す日には、記録した事実を持ち寄って判定します。判定は四つに分かれます。特定の製品を良し悪しで断じるためではなく、目の前の子どもに合っているかを確かめるための区分です。

| 観察されたこと | 判定 | 次にすること |
|---|---|---|
| 目的の場面で参加・表現・理解が増え、本人が自分で使っている | 続ける | 使う場面を一つだけ広げるか検討し、次の見直す日を決める |
| 参加は増えたが、設定や操作に手間がかかり、本来の活動より操作に時間を取られている | 調整する | 設定を一つだけ変え、同じ観察項目で同じ期間だけ試し直す |
| 解決したい困難や目標と、ツールでできることがずれている | 変える | 必要な機能の記述に戻り、候補出しからやり直す |
| 本人が使いづらさや抵抗を示す、または実際にはあまり使われていない | いったんやめる | 場面と目標の設定に戻り、ICT以外の手段も含めて検討し直す |

「調整する」で変える設定は、一度に一つだけにします。速度と読み上げ範囲と配色を同時に変えると、次の見直しの日に何が効いたのかが分かりません。

判定の結果は、続ける場合も含めて記録に残します。残っていないと、担当が替わったときに、選んだ理由も見直した経緯も引き継げません。

## 一つの場面を最初から最後まで通した例

以下は完全な架空の例です。実在する児童生徒・学校・製品とは関係がありません。分類名ではなく機能で候補を出し、判定まで進むとどうなるかを示すために作ったものです。

**場面の観察**：国語の時間、教科書の本文を各自で読む場面。他の子が読み終えるころに手が止まったままで、そのあとの話し合いが始まる前に本人の活動が終わらない。妨げられているのは主に「理解」で、結果として「参加」も欠けている。

**目標**：本文を読む場面で内容を把握し、そのあとの話し合いに一言でも入れるようにする。

**必要な機能**：本文を音声で受け取れること。いま読んでいる箇所が視覚的に分かること。本人が自分で止める・戻すができること。

**分類と候補**：目的別の分類では「読む・書く」。まず端末の標準機能を確認し、読み上げ機能があったため候補Bとする。読んでいる箇所の表示に不足がある可能性を見て、読み上げアプリを候補Aとして並べる。候補比較シートを埋めた段階で、候補Aは「通信が使えないときの動作」が公式ヘルプで確認できず「要確認（情報担当に確認）」のまま。前提の確認も候補Aは未了だったため、まず候補Bから試すことにする。

**試用の条件**：期間は3週間。場面は国語の本文を各自で読む時間のみ。見るのは担任と特別支援教育コーディネーター。記録するのは「本人が自分で再生・停止できたか」「本文を読み終えたか」「そのあとの話し合いで発言があったか」の三つ。見直す日は3週間後の学年会の日。

**観察（3週間の記録から）**：再生と停止は初日から本人が操作できた。本文を読み終えた回数は9回中7回で、試用前より増えた。話し合いでの発言は9回中2回。3週目に本人から「速い」という発話があり、読み終えたあとに内容を聞くと、後半の展開が入っていないことがあった。

**判定**：「調整する」。参加は増えているが、読み上げの速度が合っていない。変えるのは速度の設定だけにし、同じ観察項目・同じ3週間で試し直す。次の見直しでも後半の理解が残らない場合は、読んでいる箇所の表示がある候補Aに戻って比較する。そのために、候補Aの「要確認」欄は試用と並行して情報担当に確認しておく。

この例で意識的に外したのは、「読みが苦手だから読み上げアプリ」と最初から製品を一つに決めることです。標準機能から試したことで、申請も費用も発生せず、3週間で判定まで進めています。

## 授業で使うときに決めておくこと

試用に入る前に、運用の側で決めておく項目です。

| 決めておくこと | 具体的に確認すること |
|---|---|
| 使う場面と時間 | いつ使い始め、いつしまうかを事前に決めているか |
| 本人の選択 | 使うかどうか・どう使うかを本人が選べる運用になっているか |
| 紙・具体物との併用 | ICT以外の方法も選べるようにしているか |
| 目的の維持 | 操作の習熟ではなく、参加が広がっているかを見ているか |
| 個人情報の管理 | 写真・音声記録の保存先、共有範囲、削除のタイミング、保護者への説明が校内ルールに沿っているか |

支援ツールを「使わせる」形にすると、使うかどうかの判断材料になる本人の反応が観察できなくなります。必要なときに自分で取り出す運用にしておくほうが、判定の材料も集まります。

→ 授業前の実機確認や、端末が使えないときの対応は[端末を使う授業の前日準備と当日のトラブル判断：実機確認10項目と切り上げの基準](/articles/giga-device-lesson-use-guide)で扱っています。

## 誰と決め、どこに位置づけるか

支援ツールの選択は、担任一人の判断で完結させない方がよい場面があります。特にAACや読み書きの支援は、本人の運動機能や言語の実態に関わるため、特別支援教育コーディネーター、言語聴覚士や作業療法士などの専門職、外部の専門機関に相談できる体制があるかを先に確認しておきます。

→ 校内で誰に・どの順で相談するかの整理は[特別支援教育における行動記録の取り方](/articles/special-needs-behavior-record-guide)で扱っています。

決めたことは、個別の教育支援計画や個別の指導計画のどこに位置づくのかを併せて整理します。「便利そうなので使ってみる」で始めた運用は、担当が替わったときに選んだ理由が残らず、続ける判断も見直す判断もできなくなります。支援の目標とツールの使用目的が対応していれば、引き継ぎの説明も保護者への説明も同じ言葉で行えます。

→ 計画への位置づけ方、および記録の共有範囲・保管・廃棄の扱いは[個別の教育支援計画・個別の指導計画の書き方](/articles/individual-education-plan-writing-guide)、配慮として記録に残す形は[合理的配慮の記録の書き方](/articles/reasonable-accommodation-school-record)で扱っています。
